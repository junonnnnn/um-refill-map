## Java walkthrough
onCreate: Android calls this when creating/recreating the Activity. It loads the XML, applies system-bar/keyboard padding, connects fields and attaches click listeners.
setContentView(R.layout.m1_activity_login): loads the named XML layout.
findViewById(R.id.m1_email): finds the EditText declared with android:id="@+id/m1_email"; R is generated by Android, not handwritten.
setOnClickListener: runs the supplied callback when that button is tapped.
handleLogin: clears old field errors, trims only email, checks the UM domain and nonempty password, then explains that Auth is unavailable. It never logs/stores the password or sends requests.
isUmEmail: checks basic email syntax and compares the domain exactly, ignoring case. This does NOT establish email ownership or verified eligibility.
setLoading: shows/hides progress and enables/disables controls. Currently called only with false because there is no asynchronous request. No fake delay or sign-in success is shown. The true state must be connected and tested with real Firebase callbacks in a later reviewed stage.
Register/Forgot Password listeners: explain the future destination; no other Activity or email request exists.
Password view-state saving is disabled. Email can use ordinary Android view-state restoration; password re-entry after recreation is intentional.
System-bar/keyboard insets pad the outer scroll container; 24dp spacing belongs to the inner form.
